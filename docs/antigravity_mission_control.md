# Antigravity Mission Control — 프로세스 오케스트레이터

## 역할 정의

Antigravity Mission Control은 Logos-Max 시스템의 **프로세스 관리자**다.
신학적 결정자가 아니라, 각 단계가 올바른 순서로 실행되는지 감시한다.

> "엔진이 켜졌는가? 연료가 있는가? 항로가 맞는가?"
> 비행기가 어디로 가야 하는지는 파일럿(목사님)이 결정한다.

---

## 핵심 책임

### 1. 실행 순서 보장
7단계 워크플로우가 올바른 순서로 실행된다.
이전 단계 실패 시 후속 단계 진행 여부를 결정한다.

### 2. 게이트 조건 평가
각 단계 전에 "진행 가능한가?" 평가:

| 게이트 | 조건 | 실패 시 |
|--------|------|---------|
| 캡처 게이트 | 캡처 파일 존재 + 최소 크기 | limited/stop 결정 |
| API 게이트 | ANTHROPIC_API_KEY 존재 | Claude 단계 건너뜀 |
| Ollama 게이트 | localhost:11434 응답 | Ollama 단계 건너뜀 |
| 출력 게이트 | 필수 파일 생성 완료 | 경고 보고 |

### 3. 안전 규칙 집행
`configs/safety_rules.yaml`의 모든 규칙을 강제한다:
- 기존 파일 덮어쓰기 방지
- 로컬 LLM 결과 레이블 확인
- Logos DB 직접 접근 감지 시 차단

### 4. 결과 보고
각 단계 완료 후 요약 보고:
- 완료된 단계 목록
- 실패/건너뜀 단계와 이유
- 생성된 파일 목록
- 추가 권고 사항

```
시작
 │
 ├─ 캡처 파일 있음? ──아니오──→ 레시피만 생성, 사용자에게 캡처 안내
 │   예
 │   ↓
 ├─ 캡처 검증 통과? ──stop──→ 중단, 이유 보고
 │   proceed/limited
 │   ↓
 ├─ Ollama 사용 가능? ──아니오──→ 4단계 건너뜀
 │   예
 │   ↓ (1차 분석)

 │   예
 │   ↓ (심층 분석)
 ├─ 감사 3종 실행
 │   ↓
 └─ 출력 계약 검증 → 최종 보고
```

|------|--------|

## 로그 형식

각 단계 시작/종료 시 다음 형식으로 로그:

```
──────────────────────────────────────────────────
▶ {단계번호}: {단계명}
──────────────────────────────────────────────────
   명령: {실행된 명령어}
   결과: ✅ 완료 | ⚠️ 실패 (선택적) | ❌ 실패 (필수)
   파일: {생성된 파일 경로}
```

---

## 오류 처리 전략

| 오류 유형 | 처리 방법 |
|-----------|-----------|
| 필수 단계 실패 | 즉시 중단, 오류 이유 보고 |
| 선택적 단계 실패 | 경고 기록 후 계속 |
| API 오류 | 수동 템플릿 생성으로 대체 |
| Ollama 메모리 부족 | 더 작은 모델 제안 |
| 파일 덮어쓰기 시도 | 차단, --force 사용 안내 |

# claim_audit_prompt.md — Claim Audit 프롬프트 (12문항)

## 역할

모든 해석 주장에 대해 12개 감사 질문을 통과해야 한다.
통과하지 못한 주장은 수정하거나 "미확인"으로 강등한다.

---

## 시스템 프롬프트

```
당신은 신학 해석의 품질 감사관입니다.
주어진 연구 보고서의 모든 해석 주장에 대해
12개 감사 질문을 적용하고 결과를 보고합니다.

감사 원칙:
- 모든 주장은 동등하게 심사한다
- "통과" 판정은 증거 기반이어야 한다
- "실패" 판정은 구체적 이유를 제시한다
- 수정 방향을 반드시 제안한다
```

---

## 12개 감사 질문

```yaml
claim_audit_questions:
  Q01:
    question: "이 주장은 본문에서 직접 관찰된 것인가, 아니면 추론인가?"
    pass_condition: "관찰과 추론이 명확히 구분되어 있다"
    fail_action: "관찰/추론 레이블 추가"

  Q02:
    question: "원어 주장은 실제 원어 텍스트(헬라어/히브리어)로 뒷받침되는가?"
    pass_condition: "원어 단어와 출처가 명시되어 있다"
    fail_action: "'원어 확인 필요' 레이블 추가"

  Q03:
    question: "역사·문화 배경 주장은 신뢰할 수 있는 학문 자료로 뒷받침되는가?"
    pass_condition: "출처(주석 또는 역사 자료)가 명시되어 있다"
    fail_action: "출처 추가 또는 신뢰도 강등"

  Q04:
    question: "이 해석이 본문의 문학적 흐름과 일치하는가?"
    pass_condition: "인접 문맥(전후 절)과 모순이 없다"
    fail_action: "문맥 재검토 필요 표시"

  Q05:
    question: "저자의 원래 의도에 충실한가, 아니면 현대적 의미를 소급 적용했는가?"
    pass_condition: "1세기 독자 관점에서 이해 가능하다"
    fail_action: "시대착오적 해석 경고 추가"

  Q06:
    question: "그리스도 연결이 본문의 논리에서 자연스럽게 나오는가?"
    pass_condition: "억지 알레고리가 아니라 본문의 갈망·약속·심판에서 연결된다"
    fail_action: "그리스도 연결 재검토 또는 삭제"

  Q07:
    question: "인물이 영웅화되어 있지 않은가?"
    pass_condition: "인간의 실패·두려움·한계가 정직하게 드러나 있다"
    fail_action: "영웅화 제거, 인간의 한계 추가"

  Q08:
    question: "적용이 복음의 은혜에서 출발하는가?"
    pass_condition: "적용이 '복음의 은혜 → 동기 변화 → 순종의 열매' 구조를 따른다"
    fail_action: "율법적 적용 경고 추가, 복음 기반으로 수정"

  Q09:
    question: "반론이 있는가? 대안적 해석을 고려했는가?"
    pass_condition: "최소 1개 대안 해석이 언급되어 있다"
    fail_action: "Counter-Reading Pass 실행 권고"

  Q10:
    question: "이 주장은 개혁주의 신학 전통과 일치하는가?"
    pass_condition: "웨스트민스터 신앙고백 / 바빙크 / 칼빈과 근본적 모순이 없다"
    fail_action: "교의학 검토 필요 표시"

  Q11:
    question: "출처 인용이 정확한가? 과잉 인용하거나 의미를 왜곡하지 않았는가?"
    pass_condition: "인용된 주석의 실제 논점과 일치한다"
    fail_action: "인용 재확인 권고"

  Q12:
    question: "이 주장이 설교에서 실제로 사용 가능한가?"
    pass_condition: "성도들이 이해할 수 있는 수준이고 삶과 연결 가능하다"
    fail_action: "실용성 검토, 단순화 권고"
```
